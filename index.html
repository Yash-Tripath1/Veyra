Detailed explanation — how the aura is made

Start with your text. Veyra sends its UTF-8 bytes through SHA-256, a one-way hashing function. The result is always 32 bytes, or 256 bits, rendered as a 64-character hexadecimal fingerprint. Change one character and the avalanche effect changes many bits across the entire digest.

Those bytes become a compact recipe rather than a random seed. Different slices control hue, the number of trajectories, harmonic frequencies, opacity, drift, particle density, and glow. Nothing is chosen by hand after hashing, so the same text always produces the same recipe.

x(t) = sin(f₁t + φ₁) + a₂ sin(f₂t + φ₂) + a₃ sin(f₃t + φ₃)
y(t) = cos(g₁t + ψ₁) + b₂ cos(g₂t + ψ₂) + b₃ cos(g₃t + ψ₃)

Each strand samples a Fourier-like combination of sine and cosine waves. In Mandala mode those strands orbit outward; Meshwork bends them into a woven coordinate field; Nebula lets their angle, radius, and phase drift. The curves are related by the hash, but they are not copied mirror images, which is why the result feels structured without becoming a conventional symmetrical mandala.

Particles are sampled along the same trajectories, so they behave like matter in the field rather than decoration placed on top. A slow time value adds breathing, rotation, and tiny shimmer without changing the underlying identity of the aura. Hovering adds only a soft background light layer; it never changes the geometry.

Share links use AES-GCM to encrypt the text and pattern recipe in the browser. The key is kept in the URL fragment, which is not sent in normal web requests. A complete link can therefore recreate the aura without a backend, while still avoiding readable text in the query string.
